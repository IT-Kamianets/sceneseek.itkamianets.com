# SceneSeek

**AI-платформа для пошуку відеофутажів.** SceneSeek має допомогти знаходити, переглядати, зберігати й упорядковувати відеоматеріали.

SceneSeek допомагає знаходити потрібні сцени за текстовим описом, а також голосовим запитом. Результати Wikimedia Commons з’являються в одній візуальній стрічці з попереднім переглядом, даними про автора й ліцензію; відео можна зберегти до власних папок.

> Поточний GitHub-репозиторій містить Angular-вебзастосунок із SSR і prerender. Реалізовані можливості описані нижче; функції, позначені як заплановані, ще розробляються.

## Для кого

- відеомонтажери;
- автори контенту;
- дизайнери;
- усі, кому потрібно швидко знаходити відеофутажі для творчих проєктів.

## Основний сценарій

1. На сторінці «Огляд» користувач відкриває рекомендації й тематичні добірки або переходить до пошуку.
2. На сторінці «Пошук» користувач описує сцену, додає фото чи шукає голосом.
3. SceneSeek показує відфільтровані результати; користувач переглядає й зберігає потрібні сцени.
4. Авторизований користувач може переглянути історію пошукових запитів, застосовані фільтри та повторити пошук.

Пошук і рекомендації розділені на окремі екрани; окремого розділу AI-агента в основній навігації немає.

## Структура сторінок і навігація

Основна навігація містить п’ять розділів:

1. **Огляд** — рекомендації, категорії та тематичні добірки; стартова сторінка застосунку.
2. **Пошук** — текстовий, голосовий і візуальний запит, фільтри, сортування та результати.
3. **Історія** — попередні пошукові запити та нещодавно переглянуті відео.
4. **Збережене** — вкладки «Уподобані» та «Мої папки».
5. **Профіль / акаунт** — особисті дані, налаштування й демонстраційний розділ Pro.

Деталі відео, окрема папка, налаштування, вхід і реєстрація є вкладеними екранами або станами цих розділів, а не окремими пунктами основної навігації. Детальні вимоги — у [технічному завданні](docs/technical-spec.md).

## Поточний стек репозиторію

| Частина              | Поточна основа                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| Web-клієнт           | Angular 22, TypeScript, Angular Router                                                                         |
| Рендеринг            | Angular SSR і prerender сторінок під час build                                                                 |
| Стилі                | Tailwind CSS 4; SCSS для структурних токенів; палітри у `src/styles/themes/theme-light.css` і `theme-dark.css` |
| Реактивність         | Zoneless Angular та Angular Signals                                                                            |
| Форми                | Signal Forms рекомендовані для нових форм                                                                      |
| Асинхронні дані      | `ngxResource()` з `@wawjs/ngx-core`, коли підходить ресурсна модель                                            |
| Переклади            | `@wawjs/ngx-translate`; зараз лише українська, з можливістю додати інші мови пізніше                           |
| Тема                 | `ThemeService` з `@wawjs/ngx-ui`; темний режим використовує токени `html[data-mode='dark']`                    |
| Іконки               | Material Symbols Outlined                                                                                      |
| Збірка і розгортання | npm, GitHub Actions, GitHub Pages; публікується `dist/app/browser`                                             |
| Середовище           | Node.js 24.15+, npm 11+                                                                                        |

Firebase Authentication інтегрований для реєстрації, входу, відновлення пароля та виходу з акаунта; Cloud Firestore зберігає збережені сцени, папки, пошукові запити й нещодавно переглянуті сцени окремо для кожного користувача. Щоб підготувати Firebase-проєкт і правила доступу, виконайте кроки з [інструкції налаштування Firebase](docs/firebase-setup.md). Інші серверні можливості ще не підключені.

## Можливості продукту

- **Огляд:** щоденні рекомендації, категорії й добірки сцен.
- **Пошук:** текстові й голосові запити до Wikimedia Commons, адаптивна сітка результатів, фільтри, сортування, відеоперегляд та атрибуція джерела.
- **Історія:** текстові й голосові запити з фільтрами; повторення та керування пошуковими записами. Нещодавно відкриті сцени можна переглянути повторно, прибрати або очистити список. Для запитів із зображенням зберігається лише факт додавання фото, сам файл не зберігається.
- **Збережене:** уподобані відео та особисті папки з пошуком і сортуванням.
- **Профіль / акаунт:** особисті дані й налаштування.
- Гостьовий режим і необов’язкова реєстрація; вхід і реєстрація належать до сценарію акаунту.
- Діалоговий AI-помічник, персоналізація, пошук точних моментів, власні відео та спільні папки — можливі подальші розширення; AI-помічник не є окремим пунктом поточної навігації.
- Демонстраційний розділ SceneSeek Pro у профілі / налаштуваннях акаунту без оплат і реальної підписки.

Детальні вимоги та перелік екранів — у [технічному завданні](docs/technical-spec.md).

## Джерела медіа

Результати пошуку надходять із Wikimedia Commons через відкритий MediaWiki API. На сторінці сцени SceneSeek показує наявні відомості про автора та ліцензію й посилання на сторінку файлу. Метадані можуть бути неповними; перевіряйте умови використання на сторінці кожного матеріалу. Рекомендації на сторінці «Огляд» залишаються демонстраційними. Пошук за вмістом фото, AI-відповідність сцен і додаткові бібліотеки ще потребують окремої інтеграції.

## Структура репозиторію

За структурою та правилами репозиторію:

```text
.github/workflows/        # автоматичне розгортання
src/
  app/
    layouts/              # спільні макети
    pages/                # сторінки з lazy loading
    feature/              # функціональні модулі та бізнес-логіка
    components/           # спільні компоненти
    services/             # спільні сервіси
  assets/
  data/
  environments/
  i18n/                   # переклади
  styles/
    _theme.scss           # спільні структурні токени
    themes/
      theme-light.css    # світла шампаньово-бордова палітра
      theme-dark.css     # темна еспресо-бордова палітра
  styles.scss             # глобальна точка входу стилів
tools/seo/                # SEO-інструменти
angular.json
package.json
```

Нові сторінки розміщувати в `src/app/pages/` і підключати lazy loading через `src/app/app.routes.ts`. Функції з власною бізнес-логікою та інтеграціями групувати в `src/app/feature/<назва>/`. Орієнтуватися на `AGENTS.md` у репозиторії щодо конкретних правил роботи.

Backend і мобільні каталоги не включені до цієї структури, бо їх ще не підтверджено як частину репозиторію.

## Запуск поточної вебоснови

З кореня репозиторію:

```bash
npm install
npm start
```

Типова адреса локальної версії — `http://localhost:4200`. Production build:

```bash
npm run build
```

Build створює `dist/app/browser` і `dist/app/server`; GitHub Pages публікує prerendered browser-вивід із `dist/app/browser`. Перевіряйте актуальні скрипти в `package.json`.

## Орієнтовна послідовність розробки

Пропозиція на основі ТЗ; це не затверджений графік релізів:

1. **Адаптувати вебоснову:** сторінки, навігацію, теми, переклади та компоненти SceneSeek у поточній Angular-структурі.
2. **Пошуковий потік:** текстовий пошук і результати; погодити API-контракт та дозволений спосіб підключення перших медіаджерел.
3. **Бібліотека користувача:** збережені сцени, папки та історія пошуку зберігаються у Firestore; далі покращити пошук і сортування в бібліотеці.
4. **Розширення:** голосовий і візуальний пошук, діалоговий AI-помічник, точні моменти, спільні папки, публікації та Pro — після визначення потрібної серверної й мобільної архітектури.

Застосунок розвивається поетапно: спочатку основний вебдосвід і акаунт, далі — збереження даних та пошукові інтеграції.

## Поточна мова інтерфейсу

Назви сторінок і весь видимий інтерфейс зараз українською. Структура перекладів зберігається так, щоб згодом додати вибір мови в налаштуваннях акаунту.

## Відкриті архітектурні рішення

- навчальний обсяг демонстраційного вебзастосунку;
- чи потрібен окремий мобільний клієнт на Ionic/Capacitor;
- чи буде backend окремим сервісом і де він розміщуватиметься;
- потреба у Storage чи Cloud Functions;
- чи потрібен окремий FastAPI API поряд із Firebase;
- AI-провайдер і моделі;
- розширення джерел відео та підвищення точності пошуку;
- демонстраційний вміст розділу Pro без цін, оплат і реального керування підпискою;
- середовища розгортання, секрети, резервне копіювання та CI/CD для майбутніх сервісів.

## Правила роботи з контентом

Демонстраційний контент позначайте як прикладовий. У поточній навчальній версії не підключайте реальні бібліотеки та не реалізуйте завантаження сторонніх матеріалів.
